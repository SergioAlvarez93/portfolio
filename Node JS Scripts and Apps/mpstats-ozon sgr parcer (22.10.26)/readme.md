# MPSTATS → Ozon SGR Parser

Автоматизированный инструмент для сбора товарной аналитики с MPSTATS, извлечения номеров свидетельств о государственной регистрации (СГР) из карточек товаров Ozon и формирования структурированного отчёта в формате Excel.

Проект объединяет три последовательных этапа обработки данных:

1. Получение товаров и аналитических показателей из MPSTATS.
2. Поиск номеров СГР на Ozon с использованием основного парсера и дополнительного механизма восстановления пропущенных данных.
3. Нормализация результатов, группировка товаров по продавцам и генерация Excel-отчёта.

Каждый этап реализован как отдельный Node.js-модуль с собственными зависимостями.

## Возможности

- Получение списка товаров из выбранной категории MPSTATS через API.
- Фильтрация товаров по наличию остатков.
- Сбор основных характеристик: ID, название, URL, бренд, продавец, выручка и количество продаж.
- Расчёт средней цены товара.
- Автоматический поиск номеров СГР на Ozon.
- Использование двух способов извлечения данных: через модальное окно Ozon и непосредственно из карточки товара.
- Повторная обработка товаров, для которых не удалось получить номер СГР.
- Нормализация номеров СГР с учётом кириллических символов, визуально совпадающих с латинскими.
- Группировка товаров по продавцам (`seller_id`).
- Расчёт суммарной выручки и количества продаж по каждому продавцу.
- Формирование Excel-отчёта с общей статистикой по продавцам и подробной информацией о товарах.

### Описание модулей

#### 1. MPSTATS Fetcher

**Директория:** `mpstats/`

Получает товарные данные через MPSTATS API.

В рамках обработки:

- Выполняется POST-запрос к API MPSTATS.
- Загружается заданный диапазон товаров выбранной категории.
- Оставляются товары, имеющие остатки на складах FBO или FBS.
- Извлекаются основные характеристики товаров.
- Рассчитывается средняя цена на основе выручки и количества продаж.

Результат сохраняется в JSON-файл `mpstats_page.json`.

Для работы необходим API-ключ MPSTATS.

#### 2. Ozon SGR Parser

**Директория:** `ozon_parcer/`

Модуль отвечает за извлечение номеров СГР из карточек товаров Ozon.

Основной парсер (`script.js`) последовательно обрабатывает товары из `mpstats_page.json`.

Для каждого товара:

1. Открывается модальное окно проверки товара Ozon.
2. Выполняется поиск номера СГР среди доступных данных.
3. Если номер найден, он сохраняется в поле `sgr_number`.
4. Если получить номер не удалось, товар остаётся с пустым значением `sgr_number`.

Для автоматизации браузера используется Puppeteer.

**Дополнительный механизм восстановления — `repair_loop.js`.**

После завершения основного парсера запускается отдельный проход по товарам, у которых `sgr_number` не заполнен.

В отличие от основного парсера, механизм восстановления обращается непосредственно к карточке товара Ozon:

- Открывает страницу товара.
- Ожидает загрузки необходимых элементов.
- Прокручивает страницу для загрузки динамического содержимого.
- Ищет номер СГР в характеристиках товара.
- При успешном обнаружении записывает результат обратно в исходный JSON.

Для снижения количества повторных запросов предусмотрена задержка между обработкой товаров. Результаты дополнительно сохраняются каждые 10 обработанных позиций.

Таким образом, второй проход позволяет получить часть данных, которые не удалось извлечь через модальное окно.

#### 3. Normalize & Excel Report

**Директория:** `normalize/`

Финальный модуль обрабатывает собранные данные и формирует итоговые отчёты.

Основные операции:

- Нормализация номеров СГР.
- Замена кириллических символов на визуально соответствующие латинские.
- Приведение данных к единому формату.
- Группировка товаров по `seller_id`.
- Подсчёт количества товаров у каждого продавца.
- Расчёт суммарной выручки и количества продаж.
- Формирование итогового JSON.
- Генерация Excel-книги с двумя листами.

**Лист «Сводка»**

Содержит агрегированную информацию по продавцам:

- Seller ID;
- название продавца;
- количество товаров;
- количество товаров с СГР;
- количество товаров без СГР;
- суммарная выручка;
- суммарное количество продаж;
- средняя цена.

**Лист «Товары»**

Содержит подробную информацию по каждому товару:

- Seller ID;
- продавец;
- ID товара;
- название;
- бренд;
- номер СГР;
- выручка;
- количество продаж;
- средняя цена;
- ссылка на карточку товара Ozon.

Ссылки на товары в Excel представлены в кликабельном формате.

## Требования

- Node.js 22 или выше.
- npm.
- API-ключ MPSTATS.
- Доступ к интернету.
- Возможность запуска Chromium для Puppeteer.

## Установка

Каждый модуль устанавливается независимо.

### 1. MPSTATS Fetcher

Создать файл `.env` на основе `.env.example`:

```env
MPSTATS_API_KEY=your_mpstats_api_key
```

Установить зависимости:

```bash
cd mpstats
npm install
```

Внешние npm-зависимости отсутствуют: используются встроенные возможности Node.js.

### 2. Ozon SGR Parser

```bash
cd ../ozon_parcer
npm install
```

При установке Puppeteer загружает необходимую версию браузера Chromium.

### 3. Normalize

```bash
cd ../normalize
npm install
```

Устанавливается библиотека ExcelJS для формирования XLSX-файлов.

## Запуск

Этапы необходимо выполнять последовательно.

### Этап 1. Получение товаров из MPSTATS

Из директории `mpstats/`:

```bash
npm start
```

После выполнения формируется файл:

```text
mpstats_page.json
```

### Этап 2. Поиск номеров СГР на Ozon

Из директории `ozon_parcer/`:

```bash
npm start
```

Основной парсер последовательно обрабатывает товары и записывает найденные номера СГР в исходный JSON.

### Этап 3. Повторная обработка пропущенных товаров

После завершения основного парсера:

```bash
npm run repair
```

Дополнительный проход пытается найти номера СГР непосредственно в карточках товаров Ozon для позиций, оставшихся без результата.

### Этап 4. Нормализация и формирование отчётов

Из директории `normalize/`:

```bash
npm start
```

Формируются итоговые файлы:

```text
mpstats_grouped.json
mpstats_report.xlsx
```

## Технические особенности

- **Модульная архитектура:** получение данных, парсинг и аналитическая обработка разделены на независимые компоненты.
- **Puppeteer:** используется для взаимодействия с динамическими страницами Ozon.
- **Двухэтапное извлечение СГР:** основной поиск через модальное окно дополняется повторным поиском непосредственно в карточке товара.
- **Промежуточное сохранение:** механизм восстановления периодически записывает прогресс обработки.
- **JSON как промежуточный формат:** данные передаются между модулями через общий файл, что позволяет повторно запускать отдельные этапы.
- **ExcelJS:** используется для создания структурированного отчёта с форматированием, фильтрами и кликабельными ссылками.

## Ограничения

- Результат парсинга зависит от доступности MPSTATS API и актуальной структуры страниц Ozon.
- Ozon может ограничивать автоматизированные запросы или изменять разметку карточек товаров.
- Не для всех товаров номер СГР может присутствовать в открытых данных.
- Повторный проход не гарантирует получение всех пропущенных номеров.
- Обработка большого количества товаров может занимать значительное время.

Проект предназначен для автоматизации сбора и структурирования товарных данных, а не для юридической проверки подлинности или действительности свидетельств о государственной регистрации.
