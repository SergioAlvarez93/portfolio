# Adding Products to a 1C-Bitrix Website

Набор Node.js-инструментов для автоматизации наполнения и сопровождения товарного каталога на сайте под управлением **1С-Битрикс**.

Проект объединяет несколько независимых модулей, которые автоматизируют импорт товаров из Excel, нормализацию наименований, интеллектуальную категоризацию с помощью ИИ, синхронизацию данных с маркетплейсом Ozon, обновление цен и остатков, а также управление изображениями товаров.

## О проекте

При работе с большим товарным каталогом значительная часть задач связана с регулярной обработкой данных из разных источников и синхронизацией информации между внешними сервисами и сайтом.

Проект решает эти задачи с помощью отдельных Node.js-скриптов, взаимодействующих с REST API 1С-Битрикс.

Каждый модуль отвечает за конкретную операцию и может запускаться независимо от остальных.

Основные направления автоматизации:

- Импорт товаров и торговых предложений из Excel.
- Нормализация наименований товаров.
- Автоматическое распределение товаров по категориям с помощью LLM.
- Синхронизация товарных данных с Ozon.
- Управление статусом новинок.
- Обновление цен и остатков.
- Массовое обновление изображений из внутреннего файлового хранилища.
- Диагностика структуры категорий каталога.

## Функциональные модули

### 1. Импорт товаров — `script.js`

Основной модуль для импорта и синхронизации товаров и торговых предложений с каталогом 1С-Битрикс.

**Возможности:**

- Чтение исходных данных из Excel.
- Нормализация наименований и извлечение характеристик товаров.
- Получение существующих товаров, торговых предложений, брендов и значений свойств из Битрикс.
- Сопоставление сущностей по штрихкодам и наименованиям.
- Создание новых и обновление существующих товаров и торговых предложений.
- Формирование результатов обработки и журнала операций.

**Результаты работы:**

- `final-table-data.json`
- `push-log.json`

### 2. Нормализация наименований — `name_normalizing/`

Модуль синхронизирует наименования торговых предложений и родительских товаров с исходной Excel-таблицей.

**Возможности:**

- Сопоставление торговых предложений с данными таблицы по штрихкодам.
- Обновление наименований торговых предложений.
- Получение родительских товаров и обновление их названий.
- Очистка наименований от технических обозначений, номеров артикулов и единиц измерения.
- Сохранение информации об успешных и неуспешных операциях.

**Результаты работы:**

- `updated-names.json`
- `failed-names.json`
- `updated-parents.json`
- `failed-parents.json`

### 3. AI-категоризация товаров — `assigning_categories_to_products/`

Модуль автоматического распределения товаров по разделам каталога с использованием LLM через OpenRouter API.

**Возможности:**

- Получение дерева разделов каталога из Битрикс.
- Сбор информации о товарах и их текущих категориях.
- Передача данных товаров и специальных инструкций классификации языковой модели.
- Получение структурированного JSON с предложенными категориями.
- Сохранение результатов AI-классификации перед применением изменений.
- Обновление разделов товаров через REST API Битрикс.

Для классификации используется специализированный системный промпт с правилами распределения продукции по тематическим категориям.

**Технологии:** OpenRouter API, Undici, `wreq-js`.

**Результаты работы:**

- `sections-tree.json`
- `products-sections.json`
- `ai-matched.json`

### 4. Управление новинками — `new_products/`

Модуль синхронизирует статус «Новинка» между Excel-таблицей и каталогом Битрикс.

**Возможности:**

- Получение списка новинок из Excel.
- Сопоставление товаров с торговыми предложениями по штрихкодам.
- Определение родительских товаров.
- Добавление товаров в раздел «Новинки».
- Установка соответствующего значения свойства товара.
- Снятие статуса «Новинка» и удаление из специального раздела, если товар отсутствует в актуальной исходной таблице.

Таким образом, модуль поддерживает актуальность раздела новинок без необходимости вручную проверять весь каталог.

**Результат работы:**

- `new-products-report.json`

### 5. Синхронизация данных Ozon — `ozon_data/`

Модуль получает товарную информацию из нескольких кабинетов Ozon Seller и переносит её в каталог 1С-Битрикс.

**Возможности:**

- Подключение к четырём кабинетам Ozon Seller.
- Получение характеристик товаров через Ozon Seller API.
- Нормализация описаний и атрибутов.
- Преобразование данных маркетплейса в формат свойств Битрикс.
- Сопоставление товаров по идентификаторам предложений и штрихкодам.
- Обновление подробных и кратких описаний товаров.
- Обновление дополнительных свойств торговых предложений.
- Формирование отчёта о результатах синхронизации.

**Результаты работы:**

- `ozon-normalized.json`
- `ozon-update-report.json`

### 6. Синхронизация цен и остатков — `price_quantity/`

Модуль обновления цен и складских остатков на основании исходной Excel-таблицы.

**Возможности:**

- Чтение цен и остатков из Excel.
- Получение торговых предложений и существующих цен из Битрикс с использованием пагинации.
- Сопоставление товаров по штрихкодам.
- Обновление складских остатков.
- Обновление существующих цен.
- Создание цен, если соответствующая запись отсутствует.
- Активация торговых предложений при обновлении остатков.
- Обнуление остатков товаров, отсутствующих в исходной таблице.

Модуль позволяет синхронизировать актуальное состояние каталога с внешним источником товарных данных.

### 7. Диагностика дерева категорий — `check_categories_tree/`

Вспомогательный модуль для проверки структуры вложенности разделов каталога и фактического распределения товаров по категориям.

**Возможности:**

- Получение торговых предложений из Битрикс.
- Определение родительских товаров.
- Получение разделов, к которым привязаны родительские товары.
- Построение полной цепочки вложенности разделов от текущей категории до корневой.
- Формирование JSON-отчёта с путями категорий для каждого торгового предложения.

Модуль помогает контролировать корректность структуры каталога и выявлять проблемы с распределением товаров.

**Результат работы:**

- `categories-report.json`

### 8. Обновление изображений — `renewing_images_on_site/`

Модуль синхронизации изображений товаров между внутренним файловым сервером компании и сайтом на 1С-Битрикс.

**Возможности:**

- Сканирование каталогов товаров на внутреннем сетевом хранилище.
- Определение товаров по 13-значному штрихкоду в названии папки.
- Поиск изображений во вложенных директориях `site`.
- Чтение изображений и кодирование файлов в Base64.
- Получение текущих изображений товаров из Битрикс.
- Сопоставление товаров по штрихкодам.
- Удаление старых изображений и загрузка новых через REST API.
- Назначение первого изображения в качестве анонсной и детальной картинки.
- Загрузка остальных изображений в дополнительную галерею `MORE_PHOTO`.

**Поддерживаемые форматы:** JPG, JPEG, PNG, WEBP, GIF.

## Установка и запуск

### Требования

- Node.js версии 22 или выше.
- Доступ к сайту на 1С-Битрикс с настроенным REST API.
- Права на чтение и изменение каталога товаров и торговых предложений.
- Исходные Excel-таблицы.
- API-ключ OpenRouter для AI-категоризации.
- Учётные данные Ozon Seller API для соответствующих кабинетов.
- Доступ к внутреннему файловому серверу для обновления изображений.

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd adding-products-to-a-1c-bitrix-website
```

### 2. Настройка окружения

Создать файл `.env` на основе `.env.example` в корневой директории проекта.

Указать необходимые ключи доступа и параметры подключения.

### 3. Установка зависимостей

Каждый модуль содержит собственный `package.json`.

Для установки зависимостей конкретного модуля необходимо перейти в его директорию и выполнить:

```bash
npm install
```

Например:

```bash
cd assigning_categories_to_products
npm install
```

### 4. Подготовка исходных файлов

Разместить Excel-файлы в соответствующих директориях:

- `table.xlsx` — основной импорт и нормализация наименований.
- `new_products/new_products.xlsx` — список новинок.
- `price_quantity/price_quantity_table.xlsx` — цены и остатки.

Для работы модуля изображений необходим доступ к внутреннему файловому серверу.

### 5. Запуск

Перейти в директорию нужного модуля и выполнить:

```bash
npm start
```

Основной скрипт импорта запускается из корневой директории проекта.

## Конфигурация

Фактические учётные данные, вебхуки и внутренние адреса не должны попадать в публичный репозиторий.

## Особенности реализации

- **Сопоставление по штрихкодам.** Основной механизм идентификации торговых предложений при синхронизации — свойство `property261`.
- **Пагинация API.** При получении больших наборов товаров и цен используются постраничные запросы к REST API Битрикс.
- **Повторные запросы.** В отдельных модулях реализованы механизмы повторных запросов с задержками при сетевых ошибках и временной недоступности API.
- **Промежуточные данные.** Результаты обработки и промежуточные структуры сохраняются в JSON для диагностики и контроля.
- **AI-классификация.** Категоризация использует структурированный ответ языковой модели и специализированные правила предметной области.
- **Обработка изображений.** Файлы передаются в Битрикс в формате Base64 через REST API.
- **Независимый запуск.** Каждый модуль предназначен для отдельного запуска и выполнения своей бизнес-задачи.

## Важные замечания

Некоторые модули выполняют массовые изменения в рабочем каталоге. Перед запуском необходимо проверять исходные данные и учитывать последствия операций:

- Модуль синхронизации цен и остатков обнуляет остатки торговых предложений, отсутствующих в исходной таблице.
- Модуль обновления изображений удаляет существующие изображения перед загрузкой новых.
- Модуль новинок снимает соответствующий статус с товаров, отсутствующих в актуальном списке.
- Модуль AI-категоризации применяет к товарам категории, предложенные языковой моделью.
- Повторные POST-запросы при потере ответа могут привести к повторному выполнению операции на стороне API.

В интеграции с Ozon используется ограничение `limit: 1000` на запрос без дополнительной обработки пагинации. При превышении этого количества товаров выгрузка может оказаться неполной.

Скрипты рассчитаны на конкретную конфигурацию каталога 1С-Битрикс: используются определённые инфоблоки, свойства, разделы и группы цен.

## Статус проекта

Проект представляет собой набор практических инструментов автоматизации, разработанных для решения реальных задач управления товарным каталогом.

В нём реализованы интеграции с внешними API, обработка больших массивов данных, автоматизация операций с каталогом, AI-классификация товаров и синхронизация мультимедийного контента.

Проект ориентирован на конкретную инфраструктуру и бизнес-процессы. Перед использованием в другой конфигурации Битрикс необходимо адаптировать идентификаторы инфоблоков, свойства и параметры подключения.

**Примечание:** проект не позиционируется как полностью протестированная CI/CD-система. Интеграционное поведение необходимо проверять в целевой среде 1С-Битрикс.
