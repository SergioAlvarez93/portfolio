# Lead Distributor

Сервис автоматизирует первичную обработку входящих лидов в Bitrix24: получает данные нового лида, классифицирует обращение с помощью языковой модели, определяет ответственного менеджера и формирует AI-справку о потенциальной компании для карточки CRM.

## Возможности

- Приём событий о новых лидах Bitrix24 через Flask webhook.
- Получение полной карточки лида через REST API Bitrix24.
- Классификация обращения на три категории с помощью YandexGPT.
- Резервная классификация через OpenRouter (если настроен API-ключ).
- Маршрутизация лидов по категориям.
- Ротация основной группы менеджеров с проверкой статуса отпуска.
- Подготовка аналитической справки о компании на основе данных лида.
- Запись назначенного менеджера и справки в карточку лида Bitrix24.

## Сценарий обработки

1. Bitrix24 отправляет событие `ONCRMLEADADD` на endpoint `/webhook`.
2. Сервис получает ID лида и запрашивает его карточку через Bitrix24 REST API.
3. По заголовку и комментарию обращения AI-модель определяет категорию.
4. Python-логика выбирает ответственного:
   - **Категория 1** — ротация между основной группой менеджеров с исключением тех, кто находится в отпуске.
   - **Категория 2** — назначенный менеджер по аптечным сетям и крупным закупкам.
   - **Категория 3** — менеджер по остальным обращениям.
5. Сервис обновляет `ASSIGNED_BY_ID`.
6. AI-модель формирует справку о потенциальной компании, после чего сервис записывает её в `SOURCE_DESCRIPTION`.

## Правила классификации

Приоритет категорий: **1 → 2 → 3**.

- **Категория 1:** СТМ, собственная торговая марка, контрактное производство, OEM, запросы прайса и общие запросы на связь.
- **Категория 2:** аптечные сети, поставки и продажи через аптеки, крупные закупки — только если нет признаков категории 1.
- **Категория 3:** остальные обращения, включая розничные вопросы, вопросы по продукту и жалобы.

Классификацию выполняет LLM по заданному промпту. Назначение менеджера, ротация и проверка отпусков реализованы Python-кодом, а не делегированы модели.

## Установка

Требуется Python 3.10+.

```bash
python -m venv .venv
```

Активация окружения:

Windows PowerShell:
```powershell
.venv\Scripts\Activate.ps1
```

Linux / macOS:
```bash
source .venv/bin/activate
```

Установка зависимостей:

```bash
pip install -r requirements.txt
```

Создайте локальный `.env` на основе шаблона:

```bash
cp .env.example .env
```

В Windows можно просто скопировать `.env.example` и переименовать копию в `.env`.

Заполните `.env` ключами YandexGPT, ID каталога и URL новых входящих вебхуков Bitrix24. OpenRouter является необязательным резервным провайдером.

Запуск:

```bash
python main.py
```

По умолчанию Flask слушает `127.0.0.1:5000`. Для приёма внешних запросов endpoint должен быть доступен Bitrix24 через корректно настроенную инфраструктуру (например, reverse proxy или защищённый туннель). Не включайте `FLASK_DEBUG=true` на рабочем сервере.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `YANDEXGPT_API_KEY` | API-ключ YandexGPT |
| `YANDEXGPT_CATALOG_ID` | Идентификатор каталога Yandex Cloud |
| `BITRIX_WEBHOOK_GET` | URL вебхука для получения лида |
| `BITRIX_WEBHOOK_LIST` | URL вебхука для получения списка лидов |
| `BITRIX_WEBHOOK_UPDATE` | URL вебхука для обновления лида |
| `BITRIX_WEBHOOK_USER` | URL вебхука для получения данных пользователя |
| `OPENROUTER_API_KEY` | Необязательный ключ резервного провайдера |
| `MAIN_MANAGERS` | ID менеджеров основной группы через запятую |
| `SPECIAL_MANAGER` | ID менеджера категории 2 |
| `DEFAULT_MANAGER` | ID менеджера категории 3 |
| `JUNK_STATUS_ID` | Код статуса некачественного лида |
| `FLASK_HOST`, `FLASK_PORT` | Адрес и порт Flask |
| `FLASK_DEBUG` | Режим отладки; по умолчанию выключен |

Остальные параметры повторных попыток, таймаутов, моделей и логирования также настраиваются через `.env`; полный перечень находится в `.env.example`.

## Безопасность

- Не публикуйте `.env`, API-ключи и URL Bitrix24 webhook с токенами.
- Используйте `.env.example` только как шаблон без реальных секретов.
- Входящие данные лидов, телефоны, email, ответы API и текст AI-анализа не записываются в лог.
- Flask debug-режим выключен по умолчанию.
- Для production-развёртывания используйте HTTPS, ограничение доступа к endpoint, WSGI-сервер и защищённое хранение секретов.
- Если токен или ключ ранее попадал в публичный репозиторий, переписку или другой неконтролируемый канал, его необходимо отозвать и выпустить заново. Простое удаление из файла не аннулирует секрет и не удаляет его из истории Git.

## Ограничения и примечания

- Результат классификации зависит от текста лида и ответа языковой модели.
- Сервис использует заданные промпты и правила маршрутизации; это не универсальная CRM-система.
- Запрос к модели для обогащения компании формирует аналитическую справку на основе доступного модели контекста. В текущей реализации отдельный поисковый API или проверка юридических данных не подключены, поэтому сведения из ответа модели требуют проверки менеджером.
- Интеграция проверяет ответы API на базовом уровне, но фактическая работа зависит от прав вебхуков, доступности Bitrix24 и настроек Yandex Cloud/OpenRouter.

## Примечание для портфолио

Перед публикацией проверьте, что в истории Git нет ранее закоммиченных секретов, а все раскрытые токены Bitrix24 и API-ключи перевыпущены. Этот репозиторий содержит демонстрационную конфигурацию и не включает реальные данные CRM.
